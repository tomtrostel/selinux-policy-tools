# SELinux Policy Tools (prototype)

Navigation and authoring help for refpolicy-style SELinux policy source: the
`.te` / `.if` / `.fc` / `.spt` files in RHEL and Fedora `selinux-policy`, and
locked-down policies derived from it (CLIP-style).

It works on **uncompiled source**. It parses the m4 structure (interfaces,
templates, `gen_require`, `optional_policy`, declarations, AV rules) without
running m4, and expands templates one step so that generated names resolve,
e.g. `http_port_t` and `corenet_tcp_bind_http_port` jump to
`network_port(http, …)` in `corenetwork.te.in`.

## Install

```
code --install-extension selinux-policy-tools-0.1.0.vsix
```

Then open the policy checkout (the folder containing `policy/`) as your
workspace. Indexing the full Fedora tree (~1,500 files) takes about 2 seconds;
the status bar shows the result.

For standalone local modules, open the module's folder instead. If the folder
has no support macros, the extension indexes the installed
`selinux-policy-devel` headers (`/usr/share/selinux/devel/include`)
automatically; install that package with `dnf install selinux-policy-devel`.

## Features

**Navigation**

* Go to definition (F12) for interfaces, templates, m4 defines, types,
  attributes, roles, booleans/tunables and object classes, including names
  generated by templates.
* Find all references (Shift+F12), e.g. every caller of an interface across
  all modules.
* Hover: interface signature, summary, parameter docs, and what it requires;
  for types, attributes and the `.fc` paths that label them; for classes, the
  full permission list (including inherited commons); tunable descriptions.
* Outline of the current file, and workspace-wide symbol search (Ctrl+T).
* **Policy Explorer** sidebar: layers → modules → types, attributes, booleans,
  interfaces and file contexts, each clickable.
* *SELinux: Open Module…* (Ctrl+Alt+M) and commands to jump between a module's
  `.te`, `.if` and `.fc`.

**Authoring**

* Completion for interfaces (inserted as snippets with named parameters),
  types, attributes, booleans and keywords; inside AV rules, completion is
  context-aware: object classes after `:`, then only the permissions valid
  for the chosen class(es), plus permission-set macros.
* Signature help while typing interface arguments, with parameter docs.
* Syntax highlighting for policy and file-context files.
* Diagnostics, each with quick fixes where possible:
  * unknown interface/macro calls (suggests the closest names);
  * unknown object classes and invalid permissions for a class
    (suggests corrections);
  * in `.if` files, types/attributes used in an interface but missing from
    its `gen_require` block (quick fix inserts the line);
  * unbalanced parentheses / m4 quotes.
  Calls inside `optional_policy` to interfaces from modules not in the tree
  are reported as information only, since the build skips them.

On the full Fedora policy tree the diagnostics produce no false warnings; the
only notices are informational, for calls into the separately shipped
`container` module.

## Settings

| Setting | Default | Purpose |
| --- | --- | --- |
| `selinux.extraIncludePaths` | `[]` | More directories to index, e.g. the full policy tree while editing local modules elsewhere |
| `selinux.useDevelHeaders` | `auto` | `auto` / `always` / `never` index the devel headers |
| `selinux.develHeadersPath` | `/usr/share/selinux/devel/include` | Devel header location |
| `selinux.diagnostics.unknownMacros` / `.classPerms` / `.genRequire` | `true` | Toggle individual checks |

## Limitations

* Structural parsing, not m4 emulation. Names produced by deep m4 tricks
  (string building with `patsubst`, `changequote`) won't resolve. Template
  expansion follows nested templates up to five levels.
* `ifdef`/`ifelse` branches are all indexed as if active.
* The `.te` files are not checked for missing `require` blocks, only `.if`
  interfaces.
* What a rule *means* after expansion (the compiled allow rules) is the next
  layer: build integration plus setools.

## Development

Plain JavaScript, no build step.

```
npm install
npm test            # drives the language server over LSP against a policy tree
npm run survey      # runs every diagnostic over a tree and summarizes, to catch false positives
npx @vscode/vsce package
```

The test scripts expect a checkout at `/tmp/ws/policy` and
`/tmp/selinux-policy/policy`; pass another path as the first argument.

Layout: `server/parser.js` (tokenizer and structural parser),
`server/indexer.js` (workspace index and template expansion),
`server/diagnostics.js`, `server/server.js` (LSP features),
`client/extension.js` (VS Code client and Policy Explorer).
